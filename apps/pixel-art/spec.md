# 픽셀 아트 에디터 — 계획 문서 (spec)

## 1. 앱 개요

16x16 격자에 마우스 클릭/드래그 또는 모바일 터치/드래그로 도트(픽셀)를 찍어 그림을 그리고, 색상 팔레트에서 색을 골라 칠하며, 완성한 그림을 선명한 업스케일 PNG로 저장할 수 있는 미니 픽셀 아트 에디터.

## 2. 파일 구조

`/apps/pixel-art/` 폴더 내부에 아래 파일만 생성한다 (완전히 자체 완결, 외부 폴더 참조 없음).

- `index.html` — 마크업 (헤더/타이틀, 16x16 캔버스 영역, 색상 팔레트 영역, 커스텀 색상 선택기, 도구 버튼(펜/지우개), Clear 버튼, PNG 저장 버튼, 다크모드 토글 버튼)
- `style.css` — 레이아웃, 팔레트/도구 스타일, 다크모드 CSS 변수, 반응형 스타일
- `script.js` — 격자 렌더링, 입력 처리(마우스/터치), 색상 상태 관리, 지우개/Clear 로직, PNG 내보내기 로직

`script.js`는 ES 모듈(`<script type="module">`)로 로드하되, 파일 수가 적으므로(3개) 내부적으로 함수 단위 분리만 하고 별도 모듈 파일로 쪼개지 않는다 (CLAUDE.md: "구조가 커지기 전까지 과도하게 분리하지 말 것" 준수). 별도의 README나 문서 파일은 생성하지 않으며, 조작 안내는 `index.html` 내 짧은 문구로 대체한다.

## 3. 핵심 로직 설계

### 3.1 16x16 격자 렌더링 방식 — canvas vs DOM div grid

**검토:**
- **DOM div grid**: `display: grid`로 16x16 = 256개의 `<div>`(또는 `<button>`) 셀을 생성. 각 셀에 CSS `background-color`로 색을 표현.
  - 장점: 클릭/터치 대상 판별이 쉬움(각 셀이 개별 엘리먼트라 `pointerenter`/`elementFromPoint` 불필요), CSS로 hover/선택 표시가 간단, 접근성(포커스 이동) 처리 용이.
  - 단점: 256개 DOM 노드는 이 규모에서는 성능 문제 없음(16x16은 작음), PNG로 저장하려면 결국 별도의 `<canvas>`로 그려서 변환해야 함(DOM은 직접 이미지로 못 만듦).
- **canvas**: 하나의 `<canvas>`에 16x16 논리 픽셀을 그림.
  - 장점: PNG 저장이 자연스러움(`canvas.toDataURL` 그대로 사용), 셀 수가 늘어나도 성능 우수.
  - 단점: 클릭 좌표 → 격자 인덱스 변환 로직이 별도로 필요, 드래그 중 셀 경계 판별을 직접 계산.

**선택: canvas 방식.**
이유: 이 앱의 핵심 산출물이 "PNG 저장"이므로, 편집용 화면과 저장용 이미지의 데이터 모델을 일치시키는 것이 가장 단순하다. 16x16 논리 격자를 하나의 상태 배열(`Uint32Array(256)` 또는 2차원 배열, 각 칸은 색상 문자열 또는 `null`=투명)로 관리하고, 화면 표시는 이 상태를 `<canvas>`에 셀 크기만큼 확대해 그리는 `render()` 함수로 통일한다. 저장 시에도 동일한 상태 배열을 1px=1픽셀 크기의 16x16 오프스크린 캔버스에 그린 뒤 업스케일하면 되므로 편집 화면과 저장 이미지 간 로직 중복이 없다.
- 화면 표시용 캔버스는 `width/height` 속성을 16 * CELL_SIZE(예: 24~32px)로 설정하고, `ctx.imageSmoothingEnabled = false`로 안티에일리어싱을 꺼서 픽셀 경계를 선명하게 유지.
- 격자선은 옵션으로 얇은 회색 선을 셀 경계에 그려 편집 편의성을 높인다(저장용 이미지에는 격자선을 넣지 않음 — 순수 그림만 저장).

### 3.2 도트 찍기 입력 처리

- **좌표 → 격자 인덱스 변환**: 공통 함수 `getCellFromEvent(e)`가 `canvas.getBoundingClientRect()`와 이벤트의 clientX/clientY(마우스) 또는 `e.touches[0].clientX/clientY`(터치)를 받아 `col = Math.floor((clientX - rect.left) / cellSize)`, `row`도 동일하게 계산 후 0~15 범위로 클램프.
- **마우스**:
  - `mousedown`: 그리기 시작 플래그(`isDrawing = true`) 설정 후 해당 셀 즉시 칠함.
  - `mousemove`: `isDrawing`이 true일 때만 현재 셀 칠함(같은 셀 반복 호출은 상태 비교로 스킵해 불필요한 재렌더 방지).
  - `mouseup`(및 `mouseleave` 시 캔버스 밖으로 나가는 경우 대비 `window`에 `mouseup` 리스너)로 `isDrawing = false`.
- **모바일 터치**:
  - `touchstart`: `isDrawing = true`, 해당 셀 칠하기, `e.preventDefault()`로 스크롤/줌 제스처와 충돌 방지.
  - `touchmove`: 동일하게 `preventDefault()` 후 현재 손가락 위치의 셀을 칠함(여러 칸 연속 드래그 지원).
  - `touchend`/`touchcancel`: `isDrawing = false`.
  - 캔버스에 `touch-action: none` CSS를 적용해 브라우저 기본 팬/스크롤 제스처와의 충돌을 원천 차단.
- 마우스와 터치 이벤트는 내부적으로 동일한 `paintCell(row, col)` 함수를 공유해 로직 중복 없이 구현.

### 3.3 색상 팔레트

- **기본 팔레트**: 12~16색 내외의 고정 프리셋 배열(예: 검정, 흰색, 회색 계열, 빨강, 주황, 노랑, 초록, 청록, 파랑, 남색, 보라, 분홍, 갈색 등 픽셀아트에서 흔히 쓰는 기본색 + 무채색). 팔레트는 버튼 그리드(`<button>` 또는 `<div>` + `background-color`)로 표시하고, 클릭 시 해당 색이 "현재 선택된 색"(`currentColor` 상태)이 되며 선택된 스와치에 테두리/체크 표시로 강조.
- **커스텀 색상**: `<input type="color">` 하나를 팔레트 옆에 배치. 사용자가 값을 바꾸면 그 색을 `currentColor`로 설정하고, 필요 시 팔레트 목록 맨 앞(또는 "최근 사용 색" 슬롯 1개)에 반영해 재사용 가능하게 함. 이 방식이면 별도의 색상 피커 UI를 직접 구현할 필요가 없어 외부 의존성 없이 브라우저 내장 기능만으로 커스텀 색상 지원 가능.

### 3.4 지우개 도구

- 도구 상태(`currentTool`: `'pen' | 'eraser'`)를 두고, 펜/지우개 버튼 토글로 전환.
- 지우개 모드에서 `paintCell(row, col)`은 해당 칸의 상태값을 `null`(투명)로 설정 — 캔버스 렌더링 시 해당 셀은 배경색(또는 체크무늬 투명 표시)으로 그려짐.
- PNG 저장 시 지워진 칸은 실제 알파 채널 투명으로 저장(`clearRect` 사용)되어, 배경이 있는 곳에 합성해도 자연스럽게 보이도록 함.

### 3.5 전체 지우기(Clear)

- Clear 버튼 클릭 시 확인 없이(혹은 간단한 `confirm()` 다이얼로그로) 상태 배열 256칸을 모두 `null`로 초기화하고 즉시 재렌더링.
- 실수 방지를 위해 버튼에 약간의 시각적 구분(경고색 등)을 주는 정도로 처리하고, 별도의 실행취소(undo) 기능은 이번 스펙 범위에 포함하지 않는다.

### 3.6 PNG 저장 — 업스케일 및 선명도 보장

- 저장 전용 오프스크린 캔버스(`document.createElement('canvas')`, `width = 16, height = 16`)에 상태 배열을 1px=1칸으로 그대로 그린 뒤(격자선 없이, 투명 칸은 `clearRect`로 비움), 다시 최종 업스케일 캔버스(예: 16 * 32 = 512px 정사각형)에 `ctx.imageSmoothingEnabled = false` 설정 후 `drawImage(smallCanvas, 0, 0, 512, 512)`로 확대 그려서 픽셀이 흐려지지 않고 각 도트가 선명한 사각형으로 유지되도록 한다.
- 업스케일 배율은 상수(`EXPORT_SCALE = 32`)로 관리해 필요 시 쉽게 조정 가능하게 한다.
- 최종적으로 `finalCanvas.toDataURL('image/png')`로 데이터 URL을 얻고, 동적으로 생성한 `<a download="pixel-art.png">` 엘리먼트의 `href`에 연결 후 `click()`을 호출해 다운로드를 트리거한다(별도 서버/업로드 없이 클라이언트에서 완결).

## 4. UI/디자인 개요

- CLAUDE.md 디자인 원칙 준수: 콘텐츠 중심, 과도한 장식/애니메이션 지양, 타이포그래피는 팔레트/버튼 라벨 정도만 사용.
- **다크모드**: `prefers-color-scheme: dark` 미디어쿼리로 자동 감지 + 수동 토글 버튼(`data-theme` 속성 전환, 선택 상태 `localStorage`에 저장). 색상은 CSS 커스텀 프로퍼티(`--bg`, `--panel-bg`, `--border-color`, `--text-color` 등)로 관리. 편집 캔버스 자체의 격자선/배경(체크무늬로 투명 표현)도 라이트/다크에 따라 대비가 유지되도록 별도 변수로 관리.
- **반응형 레이아웃**: 모바일 퍼스트로 작성.
  - 작은 화면: 캔버스를 화면 폭에 맞춰 정사각형으로(`max-width: 100vw` 기준, `aspect-ratio: 1/1`), 팔레트/도구 버튼은 캔버스 아래에 flexbox로 줄바꿈 배치(`flex-wrap: wrap`), 터치하기 쉽도록 팔레트 스와치와 버튼에 충분한 크기(최소 40px 내외) 확보.
  - 넓은 화면: 캔버스를 좌측(또는 중앙), 팔레트·도구·저장 버튼을 우측 사이드 패널로 배치하는 2단 레이아웃(CSS Grid나 flexbox의 미디어쿼리 분기로 처리).
- **팔레트/도구 배치**: 팔레트 스와치 그리드 → 커스텀 색상 피커 → 펜/지우개 토글 → Clear 버튼 → PNG 저장 버튼 순서로 논리적 그룹을 나누어 배치. 현재 선택된 색/도구는 시각적으로 명확히 강조(테두리, 배경 대비 등).

## 5. 외부 의존성 여부

없음. 순수 HTML/CSS/JavaScript(ES 모듈)로만 구현하며, canvas 2D API와 `<input type="color">` 등 브라우저 내장 기능만 사용한다. CDN 라이브러리나 npm 패키지를 사용하지 않는다.
