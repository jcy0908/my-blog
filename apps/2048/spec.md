# 2048 게임 — 계획 문서 (spec)

## 1. 게임 개요

방향키(또는 모바일 스와이프)로 4x4 격자 위의 숫자 타일을 밀어 같은 숫자끼리 합치며, 2048 타일 생성을 목표로 하는 싱글플레이 퍼즐 게임. 현재 점수와 최고 점수를 함께 표시한다.

## 2. 파일 구조

`/apps/2048/` 폴더 내부에 아래 파일만 생성한다 (완전히 자체 완결, 외부 폴더 참조 없음).

- `index.html` — 게임 마크업 (헤더/타이틀, 점수판 영역, 4x4 게임 보드 컨테이너, 새 게임 버튼, 승리/패배 오버레이, 다크모드 토글 버튼)
- `style.css` — 레이아웃, 타일 색상/애니메이션, 다크모드 CSS 변수, 반응형 스타일
- `script.js` — 게임 상태 관리, 입력 처리(키보드/터치), 슬라이드·병합 로직, 점수 계산, localStorage 연동, 렌더링
- (선택) `README.md`는 만들지 않음 — CLAUDE.md 컨벤션상 불필요한 문서 생성 금지, index.html 자체에 간단한 조작 설명(방향키/스와이프 안내 문구)을 넣는 것으로 대체

`script.js`는 ES 모듈(`<script type="module">`)로 로드하되, 파일 수가 적으므로(3개) 내부적으로 함수 단위 분리만 하고 별도 모듈 파일로 쪼개지 않는다 (CLAUDE.md: "구조가 커지기 전까지 과도하게 분리하지 말 것" 준수).

## 3. 핵심 로직 설계

### 3.1 그리드 크기
- 4x4 (권장값 채택). 내부적으로 `board`는 길이 16의 1차원 배열 또는 4x4 2차원 배열(`number[][]`, 빈 칸은 `0` 또는 `null`)로 표현.

### 3.2 타일 스폰 규칙
- 게임 시작 시 빈 칸 중 무작위 2곳에 타일 스폰.
- 매 유효한 이동(보드 상태가 실제로 변한 경우) 후, 빈 칸 중 무작위 1곳에 새 타일 스폰.
- 스폰 값: 90% 확률로 `2`, 10% 확률로 `4`.
- 이동으로 인해 보드에 변화가 없으면(막힌 방향) 새 타일을 생성하지 않는다.

### 3.3 입력 처리 및 슬라이드/병합 로직
- **키보드**: `keydown` 이벤트로 `ArrowUp/ArrowDown/ArrowLeft/ArrowRight` 감지, `preventDefault()`로 스크롤 방지.
- **슬라이드 알고리즘**: 각 방향에 대해 행 또는 열 단위로 처리.
  1. 이동 방향 기준으로 각 라인(행/열)에서 빈 칸(0)을 제거해 압축.
  2. 압축된 라인을 순서대로 순회하며 인접한 같은 값을 1회만 병합(병합된 타일은 같은 턴에 재병합되지 않도록 플래그 처리).
  3. 병합 후 다시 압축하여 이동 방향 끝에 정렬.
  4. 병합 시 두 타일 값의 합을 점수에 누적.
- 4방향 모두 동일한 핵심 함수(예: 왼쪽 이동 로직)를 재사용하도록 보드를 회전/전치한 뒤 왼쪽 이동을 적용하고 다시 되돌리는 방식으로 구현해 코드 중복 최소화.
- 이동 전/후 보드 상태를 비교하여 변화 여부 판정(스폰 여부 및 애니메이션 트리거에 사용).

### 3.4 모바일 터치 스와이프 지원
- 지원한다. `touchstart`에서 시작 좌표 기록, `touchend`(또는 `touchmove` 누적)에서 종료 좌표와의 델타(dx, dy) 계산.
- `Math.abs(dx)`와 `Math.abs(dy)`를 비교해 더 큰 축을 스와이프 방향으로 판정, 최소 스와이프 거리(예: 20~30px) 임계값을 두어 오탐 방지.
- 좌우/상하 판정 후 키보드 입력과 동일한 이동 처리 함수를 호출(로직 재사용).
- `touch-action: none` 또는 `overscroll-behavior`를 보드 컨테이너에 적용해 스와이프 시 페이지 스크롤/바운스 방지.

### 3.5 점수판
- **현재 점수**: 매 병합마다 두 타일 값의 합을 누적해 표시. 새 게임 시작 시 0으로 초기화.
- **최고 점수**: `localStorage`(예: 키 `2048-best-score`)에 저장. 현재 점수가 최고 점수를 넘어서면 즉시 갱신 및 저장.
- 점수판 UI는 "SCORE"와 "BEST" 두 박스로 구성, 병합 시 획득 점수를 잠깐 떠오르는 `+n` 텍스트로 표시(선택적 애니메이션, 과하지 않게).

### 3.6 승리/패배 조건
- **승리**: 보드에 `2048` 값의 타일이 처음 생성되는 순간 승리 오버레이 표시("You Win" + 계속하기/새 게임 버튼). "계속하기" 선택 시 승리 이후에도 계속 플레이 가능(2048 초과 타일 허용).
- **패배**: 보드가 가득 찼고(빈 칸 없음), 상하좌우 어느 방향으로도 병합 가능한 인접 쌍이 없을 때 패배 오버레이 표시("Game Over" + 새 게임 버튼).
- 매 유효한 이동 후 승리/패배 조건을 검사하는 순서: 이동 적용 → 새 타일 스폰 → 승리 검사(최초 1회만 트리거) → 패배 검사.

## 4. UI/디자인 개요

- CLAUDE.md 디자인 원칙을 따름: 콘텐츠 중심, 과도한 장식/애니메이션 지양.
- **다크모드**: `prefers-color-scheme: dark` 미디어쿼리로 자동 감지 + 수동 토글 버튼(클릭 시 `data-theme` 속성 전환, 선택 상태는 `localStorage`에 저장해 재방문 시 유지). 색상은 CSS 커스텀 프로퍼티(`--bg`, `--tile-bg-2`, `--tile-bg-4`, ... `--text-color` 등)로 관리해 라이트/다크 테마 전환 시 값만 교체.
- **반응형 레이아웃**: 모바일 퍼스트로 작성. 게임 보드는 `vw` 기반 또는 `aspect-ratio: 1 / 1` + `max-width`로 정사각형 유지, CSS Grid(`display: grid; grid-template-columns: repeat(4, 1fr)`)로 4x4 타일 배치. 작은 화면에서도 점수판/버튼이 세로로 자연스럽게 쌓이도록 flexbox 사용. 타일 폰트 크기는 자릿수(값 크기)에 따라 상대 단위로 축소(`clamp()` 등) 검토.
- 타일 색상은 숫자 값별로 단계적 배색(2048 오리지널과 유사한 팔레트를 라이트/다크 각각 정의).

## 5. 외부 의존성 여부

없음. 순수 HTML/CSS/JavaScript(ES 모듈)로만 구현하며, CDN 라이브러리나 npm 패키지를 사용하지 않는다. localStorage는 브라우저 내장 API로 별도 의존성이 아니다.
