링크를 눌러 다른 페이지로 갔다가 뒤로 가기를 눌렀을 때, 페이지가 새로 로딩되지 않고 그 자리 그대로 즉시 복원되는 경우가 있다. 매번 스크립트가 재실행되는 줄 알았는데, 사실 브라우저가 페이지 전체를 메모리에 "얼려서" 들고 있다가 그대로 꺼내 보여주는 것이었다.

## bfcache는 무엇을 캐싱하나

**bfcache(back/forward cache)**는 페이지를 떠날 때 DOM, JS 힙, 스크롤 위치까지 포함한 전체 상태를 메모리에 그대로 보존한다. 뒤로/앞으로 이동하면 그 스냅샷을 그대로 복원하기 때문에, HTML을 다시 파싱하고 스크립트를 처음부터 실행하는 과정이 통째로 생략된다.

## 페이지가 얼렸다가 다시 깨어난다

캐시에 들어가는 순간 페이지는 **freeze** 상태가 되어 타이머나 네트워크 요청이 멈춘다. 복원될 때는 `pageshow` 이벤트가 발생하는데, `event.persisted`가 `true`면 이 페이지가 캐시에서 복원된 것임을 알 수 있다.

```
window.addEventListener("pageshow", (event) => {
  if (event.persisted) {
    console.log("bfcache에서 복원됨");
  }
});
```

## 캐싱을 막는 흔한 실수

`unload` 이벤트 리스너를 등록하면 많은 브라우저가 해당 페이지를 bfcache 대상에서 제외해버린다. 대신 `pagehide`를 쓰고, 페이지를 떠날 때 정리할 작업이 있다면 `pagehide`나 `visibilitychange`에서 처리하는 편이 안전하다.

결국 bfcache는 서버 재요청이나 스크립트 재실행 없이 "떠날 때 그 모습 그대로" 페이지를 되살려주는 브라우저 최적화이며, `unload` 대신 `pagehide`를 쓰는 작은 습관이 이 혜택을 지켜준다.
