함수를 반환하는 함수를 쓰다 보면 바깥 함수가 끝났는데도 그 안의 변수를 계속 참조하는 코드를 종종 본다. 오늘은 이 동작의 정체인 클로저(Closure)를 정리했다. 함수와 함수가 선언될 당시의 렉시컬 환경이 묶여서 함께 살아남는 현상이다.

## 렉시컬 스코프가 핵심이다

자바스크립트 함수는 호출된 위치가 아니라 정의된 위치를 기준으로 상위 스코프를 찾는다. 내부 함수가 외부 함수의 변수를 참조하면, 외부 함수 실행이 끝나도 그 변수는 가비지 컬렉션되지 않고 내부 함수와 함께 남는다.

## 카운터 예시로 보기

```
function createCounter() {
  let count = 0;
  return function () {
    count += 1;
    return count;
  };
}

const counter = createCounter();
counter(); // 1
counter(); // 2
```

`createCounter` 는 이미 끝났지만 반환된 함수는 여전히 `count` 를 기억하고 증가시킨다. 이게 바로 클로저다.

## 반복문에서의 흔한 함정

`var` 로 반복문 변수를 선언하면 함수 스코프라서 모든 클로저가 같은 변수를 공유해 마지막 값만 참조하게 된다. `let` 은 블록마다 새 바인딩을 만들기 때문에 반복마다 독립된 값을 클로저가 기억한다. 이 차이 때문에 `setTimeout` 을 반복문 안에서 쓸 때 결과가 달라진다.

클로저는 특별한 문법이 아니라 함수와 그 정의 시점의 스코프가 함께 묶이는 자연스러운 결과이며, 이 원리를 알면 상태를 캡슐화하거나 반복문 버그를 피하는 데 도움이 된다.
