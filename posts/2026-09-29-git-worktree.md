---
title: 브랜치 하나에 폴더 하나, git worktree
date: 2026-09-29
tags: [Git, 워크플로우]
---

작업 중인 브랜치를 두고 급한 버그 브랜치로 잠깐 옮겨야 할 때, 매번 `git stash`로 변경사항을 숨겼다가 나중에 다시 꺼내는 게 번거로웠다. `git worktree`를 쓰면 저장소 하나에 브랜치별로 독립된 작업 폴더를 여러 개 만들 수 있어서, stash 없이도 두 브랜치를 동시에 열어둘 수 있다.

## worktree가 하는 일

하나의 `.git` 디렉터리를 공유하면서, 브랜치마다 별도의 체크아웃 폴더를 붙여준다. 각 폴더는 서로 다른 브랜치를 체크아웃한 상태를 유지하고, 커밋 기록과 원격 정보는 그대로 공유한다.

```
git worktree add ../my-blog-hotfix hotfix-branch
```

이 명령을 실행하면 `../my-blog-hotfix` 폴더가 새로 생기고, 거기서 `hotfix-branch`를 체크아웃한 채 바로 작업할 수 있다. 원래 폴더의 작업 내역은 그대로 남아 있다.

## 같은 브랜치는 두 곳에서 못 연다

worktree는 브랜치 하나당 체크아웃을 하나만 허용한다. 이미 다른 worktree에서 체크아웃 중인 브랜치를 또 체크아웃하려 하면 Git이 막는다. 그래서 새 작업을 시작할 때는 새 브랜치를 만들어 붙이는 편이 자연스럽다.

## 정리는 잊지 말기

다 쓴 worktree는 폴더를 지운다고 끝나는 게 아니라 `git worktree remove`로 정리해줘야 메타데이터가 깨끗하게 지워진다.

```
git worktree remove ../my-blog-hotfix
git worktree list
```

`list`로 현재 연결된 worktree들을 확인해두면, 어디에 뭘 열어뒀는지 잊어버리는 일을 줄일 수 있다.

정리하면, worktree는 stash나 별도 클론 없이도 여러 브랜치를 동시에 다룰 수 있게 해주는 기능이다. 브랜치 하나당 폴더 하나가 붙는다는 제약만 기억하면, 급한 컨텍스트 전환이 필요할 때 유용하게 쓸 수 있다.
