같은 이미지를 새로고침할 때마다 다시 받아온다면 사이트가 느려질 수밖에 없다. 브라우저가 이미 받은 파일을 언제 다시 쓰고 언제 새로 요청할지는 서버가 응답에 실어 보내는 `Cache-Control` 헤더가 결정한다.

## max-age와 no-cache는 다르다

`Cache-Control: max-age=3600`은 응답을 1시간 동안 신선하다고 보고, 그 안에는 서버에 묻지도 않고 캐시를 그대로 쓴다. 반면 `no-cache`는 캐시를 저장은 하되 매번 서버에 유효성을 확인받고 쓰라는 뜻이라, 이름과 달리 캐시를 아예 안 쓰는 게 아니다. 정말 저장 자체를 막으려면 `no-store`를 써야 한다.

## 유효성 검사는 ETag로

캐시 기간이 지나도 파일 내용이 그대로라면 다시 받을 필요는 없다. 이때 서버가 응답에 담아준 `ETag` 값을 다음 요청의 `If-None-Match`에 실어 보내면, 내용이 같을 경우 서버는 본문 없이 `304 Not Modified`만 돌려준다.

```
Cache-Control: max-age=3600
ETag: "a1b2c3"
```

정적 자산은 `max-age`를 길게 주고 파일명에 해시를 붙여 무효화하는 방식이 흔하며, 자주 바뀌는 API 응답은 `no-cache`와 `ETag`를 조합해 트래픽은 줄이면서도 최신 상태를 보장한다. 오늘은 "캐시를 쓸지"와 "캐시가 최신인지 확인할지"가 서로 다른 문제라는 걸 정리했다.
