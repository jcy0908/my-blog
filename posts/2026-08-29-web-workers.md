title: 메인 스레드를 막지 않는 법, 웹 워커
date: 2026-08-29

---

자바스크립트는 싱글 스레드라서 무거운 계산을 돌리면 그동안 화면이 멈춘다. 버튼도 안 눌리고 스크롤도 안 되는 그 답답한 순간, 해결책이 바로 웹 워커다. 오늘은 워커가 메인 스레드와 어떻게 분리되어 동작하는지 정리했다.

## 별도의 스레드, 별도의 세계

`new Worker('worker.js')`로 워커를 만들면 브라우저는 완전히 독립된 스레드에서 그 스크립트를 실행한다. 워커 안에서는 `window`나 DOM에 접근할 수 없다. 화면을 직접 건드릴 수 없는 대신, 메인 스레드가 하던 무거운 계산을 떠맡아도 화면은 얼어붙지 않는다.

## 메시지로만 대화한다

메인 스레드와 워커는 변수를 공유하지 않고 `postMessage`로 메시지를 주고받는다. 데이터는 복사되어 전달되기 때문에, 워커 쪽에서 값을 바꿔도 원본에는 영향이 없다.

```
// main.js
const worker = new Worker('worker.js');
worker.postMessage(1000000);
worker.onmessage = (e) => console.log('결과:', e.data);

// worker.js
onmessage = (e) => {
  let sum = 0;
  for (let i = 0; i < e.data; i++) sum += i;
  postMessage(sum);
};
```

이 구조 덕분에 큰 숫자를 더하는 동안에도 메인 스레드는 다른 이벤트를 자유롭게 처리한다.

## 언제 꺼내 쓰면 좋을까

이미지 처리, 대용량 JSON 파싱, 복잡한 정렬처럼 CPU를 오래 붙잡는 작업이 후보다. 반대로 짧게 끝나는 작업까지 워커로 보내면 메시지를 주고받는 오버헤드가 더 커질 수 있다. 워커 생성 비용도 있으니 자주 반복되는 작업이라면 워커를 매번 새로 만들기보다 하나를 계속 재사용하는 편이 낫다.

정리하면, 웹 워커는 무거운 계산을 메인 스레드 밖으로 빼내 화면이 멈추지 않게 해주는 도구이며, DOM에 접근할 수 없고 메시지로만 통신한다는 제약을 이해하고 써야 제대로 효과를 본다.
