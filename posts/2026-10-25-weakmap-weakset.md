title: 가비지 컬렉터를 방해하지 않는 자료구조, WeakMap과 WeakSet

DOM 요소에 부가 데이터를 붙이려고 `Map`을 썼다가, 요소가 화면에서 사라진 뒤에도 메모리에서 안 빠지는 걸 본 적이 있다. 원인은 `Map`이 키를 **강한 참조**로 들고 있기 때문이다. `WeakMap`과 `WeakSet`은 바로 이 문제를 풀기 위한 자료구조다.

## 강한 참조와 약한 참조

일반 `Map`은 키를 참조로 붙잡아 두므로, 다른 곳에서 더는 그 객체를 쓰지 않아도 `Map` 안에 남아 있으면 가비지 컬렉터가 수거하지 못한다. `WeakMap`의 키는 **약한 참조**라서, 외부에서 참조가 끊기는 즉시 키-값 쌍 전체가 수거 대상이 된다.

## 사용 예시

```js
const cache = new WeakMap();

function attach(el, data) {
  cache.set(el, data);
}

el = null; // 참조가 끊기면 WeakMap 항목도 함께 사라진다
```

`WeakSet`도 같은 원리로, 객체의 존재 여부만 약하게 추적할 때 쓴다.

## 제약과 쓰임새

`WeakMap`과 `WeakSet`은 키로 객체만 허용하고, `size`나 순회(`forEach`, `for...of`)를 지원하지 않는다. 언제 수거될지 예측할 수 없어서 목록을 나열하는 용도로는 쓸 수 없기 때문이다. 대신 DOM 노드별 메타데이터 저장, 비공개 필드 흉내, 방문 여부 체크처럼 "메모리 누수 없이 객체에 딱지를 붙이는" 용도에 적합하다.

메모리를 아끼려고 일반 `Map`을 쓰는 대신, 생명주기를 외부 객체에 맡기고 싶을 때는 `WeakMap`과 `WeakSet`을 쓰면 된다. 순회가 필요 없고 키가 객체뿐이라는 제약만 기억하면, 누수 걱정 없는 캐시를 아주 간단하게 만들 수 있다.
