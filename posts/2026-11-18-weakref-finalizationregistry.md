오늘은 일반 객체 참조와 달리 가비지 컬렉션을 막지 않는 `WeakRef`와, 객체가 정리될 때 콜백을 받는 `FinalizationRegistry`를 알아봤다. 캐시나 DOM 노드와 연결된 보조 데이터를 다룰 때, 원본이 사라져도 참조 때문에 메모리에 계속 남는 문제를 해결하는 데 쓰인다.

## 일반 참조와 WeakRef의 차이

객체를 변수나 배열에 담아두면 그 참조가 살아있는 동안 가비지 컬렉터는 해당 객체를 수거하지 못한다. `WeakRef`로 감싼 참조는 다르다. 가비지 컬렉터는 이 참조를 무시하고 언제든 원본 객체를 정리할 수 있다. `deref()`를 호출하면 아직 살아있으면 객체를, 이미 정리됐으면 `undefined`를 돌려준다.

```js
const ref = new WeakRef(largeObject);
const obj = ref.deref();
if (obj) {
  // 아직 살아있을 때만 사용
}
```

## FinalizationRegistry로 정리 시점 감지

`FinalizationRegistry`는 등록해둔 객체가 실제로 수거될 때 콜백을 실행해준다. 외부 리소스를 닫거나 로그를 남기는 용도로 쓸 수 있지만, 가비지 컬렉션 시점은 엔진이 결정하므로 콜백이 언제 호출될지는 보장할 수 없다.

## 언제 조심해야 할까

둘 다 캐시 구현처럼 "있으면 재사용하고 없으면 새로 만든다"는 패턴에 어울린다. 하지만 일반적인 메모리 관리나 리소스 해제 로직을 대신하는 용도로는 적합하지 않다. 콜백이 언제 올지, 혹은 영영 안 올 수도 있다는 점을 전제로 설계해야 한다.

결국 `WeakRef`와 `FinalizationRegistry`는 캐시처럼 특수한 상황을 위한 보조 도구일 뿐이며, 일반적인 메모리 관리나 리소스 해제를 대체할 수는 없다는 점을 기억해야 한다.
