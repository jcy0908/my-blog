버튼에 마우스를 올렸을 뿐인데 스크롤이 뚝뚝 끊긴 적이 있다면, 범인은 대부분 리플로우다. 브라우저가 화면을 그리는 과정을 알면 왜 어떤 스타일 변경은 가볍고 어떤 건 무거운지 이해할 수 있다.

## 렌더링 파이프라인

브라우저는 HTML과 CSS를 파싱해 DOM과 CSSOM을 만들고, 이를 합쳐 렌더 트리를 구성한다. 이후 각 요소의 위치와 크기를 계산하는 레이아웃(리플로우) 단계를 거쳐, 픽셀을 실제로 채워 넣는 페인트(리페인트) 단계로 이어진다. 마지막으로 레이어를 합성하는 컴포지트 단계가 있다.

## 리플로우가 비싼 이유

`width`, `top`, `margin`처럼 요소의 크기나 위치를 바꾸는 속성은 레이아웃을 다시 계산해야 한다. 이 계산은 부모와 형제 요소에도 영향을 줄 수 있어 트리 전체로 퍼지기 쉽다. 반면 `color`나 `background-color`는 레이아웃에 영향을 주지 않으니 리페인트만 일어난다.

## 합성만으로 끝내는 방법

`transform`과 `opacity`는 별도의 컴포지트 레이어에서 처리되어 레이아웃과 페인트를 건너뛸 수 있다. 그래서 애니메이션을 만들 때는 `left` 대신 `transform: translateX()`를 쓰는 게 훨씬 부드럽다.

```css
/* 무거움: 매 프레임마다 리플로우 발생 */
.box { left: 100px; }

/* 가벼움: 컴포지터에서만 처리 */
.box { transform: translateX(100px); }
```

화면이 다시 그려지는 과정은 레이아웃, 페인트, 컴포지트 세 단계로 나뉘고, 어떤 CSS 속성을 건드리느냐에 따라 건너뛸 수 있는 단계가 달라진다. 애니메이션이 버벅인다면 우선 무엇을 바꾸고 있는지부터 확인하는 습관을 들이면 좋다.
