이상한 코드 한 줄을 발견했을 때 "왜 이렇게 되어 있지?"라는 의문이 들면, 커밋 로그 전체를 뒤지는 대신 그 줄만 집어서 역사를 물어볼 수 있다는 걸 오늘 알았다.

## 줄 단위로 작성자 추적하기

`git blame`은 파일의 각 줄이 마지막으로 어느 커밋에서, 누구에 의해, 언제 바뀌었는지 보여준다.

```
git blame app.js
```

커밋 해시와 작성자, 날짜가 줄마다 붙어 나오기 때문에 "이 조건문은 왜 생겼을까"를 바로 해당 커밋 메시지로 거슬러 올라갈 수 있다. 특정 줄 범위만 보고 싶으면 `-L` 옵션으로 좁힐 수 있다.

```
git blame -L 10,20 app.js
```

## 공백만 바뀐 커밋 건너뛰기

들여쓰기를 통일하거나 세미콜론만 정리한 커밋이 끼어 있으면 진짜 로직을 바꾼 커밋을 찾기 어렵다. `-w` 옵션을 주면 공백 변경은 무시하고 그 전 커밋으로 넘어가서 추적해준다.

```
git blame -w app.js
```

## 포맷팅 커밋 자체를 무시하기

prettier나 eslint --fix처럼 파일 전체를 한 번에 다시 포맷팅한 커밋이 있다면, 그 커밋 해시를 `.git-blame-ignore-revs` 파일에 적어두고 `git config blame.ignoreRevsFile .git-blame-ignore-revs`로 등록하면 blame이 그 커밋을 건너뛰고 더 의미 있는 이전 커밋을 보여준다.

## 요약

`git blame`은 코드 한 줄의 변경 이력을 바로 찾아주는 도구로, `-L`로 범위를 좁히고 `-w`나 `ignoreRevsFile`로 의미 없는 변경을 걸러내면 "누가 왜 이렇게 바꿨는지"를 훨씬 빠르게 추적할 수 있다.
