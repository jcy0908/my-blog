z-index 값을 아무리 높여도 다른 요소 뒤에 가려지는 경험은 CSS를 다루다 보면 한 번쯤 겪게 된다. 원인은 단순한 숫자 비교가 아니라 **스태킹 컨텍스트(stacking context)** 라는 별도의 쌓임 단위 때문이다.

## 스태킹 컨텍스트란

스태킹 컨텍스트는 요소들이 z축 방향으로 쌓이는 독립적인 그룹이다. 하나의 컨텍스트 안에서만 z-index 값이 서로 비교되며, 다른 컨텍스트에 속한 요소와는 직접 비교되지 않는다.

## 컨텍스트가 생기는 조건

`position: relative`에 z-index를 지정하거나, `opacity`가 1 미만이거나, `transform`, `filter`를 사용하면 새로운 스태킹 컨텍스트가 만들어진다. 부모가 컨텍스트를 만드는 순간, 자식의 z-index는 그 부모 안에서만 의미를 가진다.

## 예시

```css
.parent {
  opacity: 0.99;
}
.child {
  position: relative;
  z-index: 9999;
}
```

위 코드에서 `.child`의 z-index가 아무리 커도 `.parent` 바깥의 형제 요소보다 위로 올라갈 수 없다. `.parent`가 이미 새 컨텍스트를 만들었기 때문이다.

z-index 문제를 만나면 값을 무작정 올리기보다, 조상 요소 중 스태킹 컨텍스트를 만드는 속성이 있는지부터 확인하는 습관을 들이면 디버깅 시간을 크게 줄일 수 있다.
