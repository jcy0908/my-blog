스크롤이나 리사이즈, 키 입력 이벤트는 짧은 시간에 수십 번씩 발생한다. 매번 함수를 실행하면 브라우저가 버벅이기 쉬운데, 디바운스와 스로틀은 이런 이벤트를 다스리는 대표적인 두 가지 방법이다.

## 디바운스: 마지막 한 번만

디바운스는 이벤트가 연달아 발생하는 동안은 실행을 미루다가, 일정 시간 동안 잠잠해지면 그때 한 번만 실행한다. 검색어 입력창의 자동완성처럼 타이핑이 끝난 뒤에만 요청을 보내고 싶을 때 적합하다.

```
function debounce(fn, delay) {
  let timer;
  return (...args) => {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), delay);
  };
}
```

## 스로틀: 일정 간격으로 한 번씩

스로틀은 이벤트가 계속 발생해도 정해진 간격마다 한 번씩만 실행되도록 제한한다. 스크롤 위치를 추적하거나 버튼 연타를 막는 것처럼, 중간중간 반응은 필요하지만 너무 자주 실행되는 건 막고 싶을 때 쓴다.

```
function throttle(fn, interval) {
  let last = 0;
  return (...args) => {
    const now = Date.now();
    if (now - last >= interval) {
      last = now;
      fn(...args);
    }
  };
}
```

## 어떤 걸 골라야 할까

"입력이 끝난 뒤 한 번"이 필요하면 디바운스, "이벤트가 진행되는 동안에도 주기적으로 반응"해야 하면 스로틀이다. 자동완성이나 폼 유효성 검사는 디바운스, 스크롤 애니메이션이나 무한 스크롤 감지는 스로틀 쪽이 더 자연스럽다.

두 기법 모두 이벤트 발생 횟수와 함수 실행 횟수를 분리해서 생각하게 해준다. 이벤트는 브라우저가 원하는 만큼 보내더라도, 실제로 무거운 작업을 언제 몇 번 실행할지는 우리가 결정할 수 있다는 것이 핵심이다.
