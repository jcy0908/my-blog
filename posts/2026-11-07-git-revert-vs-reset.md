---
title: 되돌리는 방법은 다르다, git revert와 git reset의 차이
date: 2026-11-07
tags: [Git]
---

되돌리고 싶은 커밋이 있을 때 `git revert`와 `git reset` 중 뭘 써야 할지 헷갈렸는데, 둘의 차이가 "이미 공유된 히스토리를 건드리는가"에 있다는 걸 알고 나니 선택이 쉬워졌다.

## git reset은 히스토리를 지운다

`git reset`은 브랜치 포인터를 과거 커밋으로 옮긴다. `--hard`를 쓰면 작업 디렉토리까지 그 시점으로 되돌리면서 이후 커밋들은 히스토리에서 사라진다. 아직 push하지 않은 로컬 커밋을 정리할 때 적합하다.

## git revert는 새 커밋을 추가한다

`git revert`는 지정한 커밋의 변경사항을 역으로 적용하는 새 커밋을 만든다. 기존 히스토리는 그대로 남고 "되돌렸다"는 사실만 기록에 추가된다.

```
git revert <commit-hash>
```

이미 원격에 push되어 다른 사람과 공유 중인 커밋을 되돌릴 때는 반드시 revert를 써야 한다.

## 요약

reset은 히스토리를 다시 쓰고 revert는 히스토리에 기록을 더한다. 공유 브랜치의 커밋을 되돌릴 때는 revert, 아직 공유하지 않은 로컬 작업을 정리할 때는 reset을 쓰면 충돌 없이 안전하게 되돌릴 수 있다.
