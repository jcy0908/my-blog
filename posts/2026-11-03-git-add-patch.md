작업하다 보면 한 파일에 서로 관련 없는 변경이 뒤섞일 때가 있다. 리팩터링 코드와 새 기능 코드가 같은 파일에 같이 들어 있으면, `git add file.js` 한 번으로는 커밋이 뒤섞여 버린다. 이럴 때 `git add -p`를 쓰면 파일 전체가 아니라 변경된 덩어리(hunk) 단위로 골라서 스테이징할 수 있다.

## hunk 단위로 고르기

`git add -p`를 실행하면 Git이 변경 사항을 여러 hunk로 나눠서 하나씩 보여주고 `y`(스테이징), `n`(건너뛰기), `s`(더 작게 split) 같은 선택을 묻는다. 한 파일 안에서도 원하는 줄만 골라 커밋에 담을 수 있다.

```
git add -p
# y - stage this hunk
# n - skip this hunk
# s - split into smaller hunks
# q - quit
```

## split로도 안 나뉠 때

`s`로도 쪼개지지 않는 큰 hunk는 `e`를 눌러 에디터로 직접 diff 텍스트를 수정해서 원하는 줄만 남길 수 있다. 조금 번거롭지만 한 줄 단위로 스테이징 범위를 조절할 수 있다.

## 스테이징 상태 확인

스테이징한 내용이 의도한 대로인지는 `git diff --staged`로 커밋 전에 바로 확인할 수 있다. 전체 diff가 아니라 스테이징 영역만 보여주기 때문에, 커밋하기 직전 마지막 점검으로 유용하다.

커밋 하나에 하나의 논리적 변경만 담는 습관은 리뷰와 git bisect, git revert를 모두 쉽게 만든다. git add -p는 이미 섞여버린 작업을 다시 깔끔한 커밋 단위로 되돌리는 가장 현실적인 도구다.
