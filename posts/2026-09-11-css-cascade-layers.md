오늘은 리셋 CSS와 컴포넌트 스타일이 뒤엉켜서 `!important`를 남발하던 코드를 보다가 `@layer`를 알게 됐다. 선택자를 더 복잡하게 만들지 않고도 우선순위를 통제할 수 있다는 점이 인상적이었다.

## 왜 필요한가

기존 CSS는 명시도(specificity)와 작성 순서로 우선순위가 정해진다. 나중에 로드된 서드파티 CSS가 내 스타일을 덮어쓰면, 선택자를 더 구체적으로 만들거나 `!important`를 붙이는 임시방편으로 대응하게 된다. `@layer`는 이 싸움을 선택자 단위가 아니라 레이어 단위로 옮긴다.

## 동작 원리

이름 붙인 레이어들은 등록된 순서대로 우선순위를 가지며, 뒤에 등록된 레이어가 앞선 레이어를 이긴다. 레이어 안의 명시도는 레이어 순서를 절대 넘어설 수 없어서, `reset` 레이어에 명시도 높은 선택자를 넣어도 나중에 온 `components` 레이어의 평범한 클래스 선택자에 진다.

```
@layer reset, base, components, utilities;

@layer reset {
  button { border: none; }
}

@layer components {
  .btn { border: 1px solid var(--color-border); }
}
```

## 레이어가 없는 스타일은 어떻게 되나

레이어를 지정하지 않고 작성한 일반 스타일은 이름 있는 모든 레이어보다 우선순위가 높다. 그래서 기존 코드를 한 번에 마이그레이션하지 않아도, 리셋이나 외부 라이브러리 CSS만 먼저 레이어로 감싸는 점진적 적용이 가능하다.

> 순서를 미리 선언하는 `@layer reset, base, components, utilities;` 문법을 먼저 써두면, 실제 규칙이 어느 순서로 작성되든 레이어 우선순위가 고정된다.

정리하면 `@layer`는 명시도 계산을 없애는 게 아니라, 그 위에 한 단계 더 큰 우선순위 축을 얹어주는 도구다. 레이어 이름만 잘 설계해도 `!important` 없이 스타일 충돌을 정리할 수 있겠다.
