파일 맨 위에 `import`를 몰아 적으면 번들러는 그 모듈들을 전부 하나의 초기 로딩 묶음에 넣는다. 정작 사용자가 클릭 한 번 안 할 수도 있는 기능까지 처음부터 다운로드하게 되는 셈이다. 동적 `import()`는 "그 코드가 실제로 필요해지는 순간"까지 다운로드를 미뤄주는 문법이다.

## import()는 함수다

정적 `import` 문과 달리 `import()`는 함수처럼 어디서든 호출할 수 있고, 모듈을 담은 프로미스를 반환한다.

```js
button.addEventListener("click", async () => {
  const { openModal } = await import("./modal.js");
  openModal();
});
```

버튼을 누르기 전까지 `modal.js`는 네트워크 요청조차 일어나지 않는다. 번들러는 이 호출을 보고 해당 모듈을 별도 청크 파일로 쪼개어, 초기 진입점 번들의 크기를 줄여준다.

## 언제 쪼개야 할까

모든 모듈을 동적으로 불러올 필요는 없다. 페이지 진입 즉시 쓰이는 코드라면 오히려 지연이 생길 뿐이다. 쪼개서 이득을 보는 경우는 보통 이렇다.

- 모달, 차트, 에디터처럼 특정 상호작용 이후에만 쓰이는 기능
- 특정 라우트에서만 필요한 페이지 단위 코드
- 사용 빈도가 낮은 관리자 전용 화면

## 실패 대비하기

`import()`는 네트워크 요청이므로 실패할 수 있다. 오프라인 상태거나 배포로 파일 해시가 바뀐 직후라면 404가 날 수 있으니, try/catch로 감싸고 사용자에게 재시도를 안내하는 편이 안전하다.

```js
try {
  const mod = await import("./chart.js");
} catch (e) {
  showRetryMessage();
}
```

결국 동적 `import()`는 "필요한 순간에 필요한 코드만" 가져오게 해주는 가장 단순한 코드 스플리팅 방법이다. 초기 로딩 속도가 느리다면, 지금 당장 안 써도 되는 코드부터 동적 import 뒤로 옮겨보는 것만으로 체감 속도가 달라진다.
