한창 기능을 만들다가 급한 버그 수정 요청이 들어오면 난감하다. 커밋하기엔 코드가 덜 됐고, 그렇다고 브랜치를 옮기면 변경사항이 걸린다. 오늘은 이럴 때 쓰는 `git stash`를 배웠다. 커밋하지 않은 변경사항을 임시 저장소에 넣어두고 작업 트리를 깨끗한 상태로 되돌려주는 명령이다.

## 변경사항 숨기기와 꺼내기

`git stash` 한 줄이면 추적 중인 파일의 수정 내용이 스택에 쌓이고 작업 트리는 마지막 커밋 상태로 돌아간다. 급한 일을 처리한 뒤 `git stash pop` 을 실행하면 가장 최근에 저장한 변경사항이 다시 적용되면서 스택에서 사라진다. 적용만 하고 스택에는 남겨두고 싶다면 `pop` 대신 `git stash apply` 를 쓰면 된다.

## 여러 개를 구분해서 관리하기

`git stash` 를 여러 번 실행하면 스택에 항목이 계속 쌓인다. `git stash list` 로 전체 목록을 확인할 수 있고, `stash@{0}`, `stash@{1}` 같은 이름으로 특정 항목만 골라 적용하거나 지울 수 있다. 나중에 알아보기 쉽도록 `git stash push -m "로그인 폼 리팩터링 중"` 처럼 메시지를 붙여두면 스택이 길어져도 헷갈리지 않는다.

## 새로 만든 파일도 포함하기

기본 `git stash` 는 아직 git이 추적하지 않는 새 파일을 건드리지 않는다. 새로 만든 파일까지 함께 치워두려면 `-u` 옵션을 붙여 `git stash push -u` 를 실행해야 한다.

```
git stash push -u -m "로그인 폼 리팩터링 중"
git checkout main
git switch -c hotfix/login-error
# 급한 수정 처리...
git checkout feature/login-form
git stash pop
```

커밋할 준비가 안 된 코드라도 git stash로 잠시 치워두면 브랜치를 자유롭게 오가며 급한 일을 처리할 수 있다는 걸 배웠다. 다음엔 스태시 충돌이 날 때 어떻게 풀어야 하는지도 살펴봐야겠다.
