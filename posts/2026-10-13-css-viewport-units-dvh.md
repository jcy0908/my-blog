모바일 사파리나 크롬에서 `height: 100vh`로 전체 화면 레이아웃을 잡으면, 스크롤할 때 주소창이 나타나고 사라지면서 화면 아래 버튼이 가려지는 문제를 겪어본 적이 있을 것이다. `vh`가 실제 보이는 화면 크기를 따라가지 못해서 생기는 버그다.

## vh의 한계

`100vh`는 브라우저가 처음 계산한 뷰포트 높이에 고정된다. 모바일에서 주소창이 사라져 뷰포트가 커져도 `vh` 값은 갱신되지 않거나, 반대로 주소창이 있을 때 기준으로 잡혀서 레이아웃이 화면보다 길어진다.

## svh, lvh, dvh

이 문제를 풀기 위해 세 가지 단위가 추가됐다.

- `svh` (small viewport height): 주소창이 **보일 때**의 작은 높이 기준
- `lvh` (large viewport height): 주소창이 **사라졌을 때**의 큰 높이 기준
- `dvh` (dynamic viewport height): 주소창 상태 변화에 따라 **실시간으로** 값이 바뀜

실무에서는 대부분 `dvh`를 쓰면 된다.

## 코드 예시

```css
.full-screen {
  height: 100vh; /* 구형 브라우저 대비 fallback */
  height: 100dvh;
}
```

fallback으로 `vh`를 먼저 적어두면, `dvh`를 모르는 브라우저는 `vh`를 쓰고 지원 브라우저는 자동으로 `dvh`를 덮어쓴다.

> 전체 화면 모달, 히어로 섹션처럼 `100vh`를 쓰는 곳은 거의 다 `dvh`로 바꿔도 안전하다.

정리하면, 모바일 브라우저의 주소창 때문에 생기는 `100vh` 레이아웃 깨짐은 `dvh` 단위로 간단히 해결할 수 있다. 오래된 환경을 지원해야 한다면 `vh`를 fallback으로 남겨두는 것만 잊지 않으면 된다.
