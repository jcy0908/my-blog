스크롤하면 뚝뚝 끊기던 애니메이션이 CSS 한 줄만 추가했는데 매끄러워진 적이 있다. 범인은 `will-change`였는데, 쓰기 전에 왜 느렸고 왜 빨라졌는지 짚어본다.

## 브라우저는 보통 뒤늦게 최적화한다

`transform`이나 `opacity`가 애니메이션되면 브라우저는 보통 그 요소를 별도의 **레이어**로 승격시켜 GPU로 합성한다. 문제는 이 승격이 애니메이션이 "시작된 후"에야 일어나서, 첫 프레임에서 레이어를 새로 만드는 비용이 그대로 끊김으로 드러난다는 점이다.

## will-change는 예고편이다

```
.card {
  will-change: transform;
}
```

`will-change: transform`은 "이 속성이 곧 바뀔 것"이라고 브라우저에 미리 알려준다. 브라우저는 애니메이션이 시작되기 전에 레이어를 준비해두므로, 실제 변화가 일어날 때 레이어 생성 비용을 건너뛸 수 있다.

## 남발하면 오히려 느려진다

레이어 하나를 유지하는 데는 메모리와 관리 비용이 든다. 모든 요소에 `will-change`를 걸어두면 레이어가 과도하게 늘어나 메모리 사용량이 커지고, 오히려 합성 성능이 떨어진다. 그래서 애니메이션이 시작되기 직전에 추가하고, 끝나면 `will-change: auto`로 되돌려 해제하는 식으로 짧게 쓰는 것이 권장된다.

결국 `will-change`는 "자주 바뀔 속성을 미리 알려줘서 레이어 생성 지연을 없애는" 힌트일 뿐, 모든 요소에 거는 만능 최적화 스위치가 아니라 애니메이션 직전에만 짧게 붙였다가 떼어내는 식으로 써야 효과를 본다.
