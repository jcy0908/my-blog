오프라인 상태에서도 앱처럼 화면이 뜨는 사이트들을 보면서 네트워크가 끊겨도 어떻게 콘텐츠를 보여주는지 궁금했는데, 그 뒤에 서비스 워커라는 별도의 스크립트가 있다는 걸 오늘 알게 됐다.

## 브라우저와 네트워크 사이의 프록시

서비스 워커는 페이지와 분리되어 실행되는 스크립트로, 웹 워커처럼 메인 스레드를 막지 않지만 `fetch` 요청을 가로챌 수 있다는 점이 다르다. 한 번 등록되면 페이지를 닫아도 백그라운드에 남아 네트워크 요청이나 푸시 알림 같은 이벤트에 반응한다.

## 캐시 우선 전략

`install` 이벤트에서 필요한 파일을 캐시에 저장해두고, `fetch` 이벤트에서 캐시에 있으면 캐시를 쓰고 없으면 네트워크로 요청하는 방식으로 오프라인 대응을 구현할 수 있다.

```
self.addEventListener('fetch', (e) => {
  e.respondWith(
    caches.match(e.request).then((res) => res || fetch(e.request))
  );
});
```

## 등록은 즉시, 적용은 별도

`navigator.serviceWorker.register()` 로 등록해도 install, activate, fetch 라는 독립된 생명주기를 거치기 때문에, 새로고침 한 번으로 최신 버전이 바로 적용되지 않고 관련 탭이 모두 닫힌 뒤에야 교체되는 경우가 많다.

서비스 워커는 브라우저와 네트워크 사이에 끼어드는 프록시 스크립트로, 캐시 전략을 직접 짜면 오프라인 지원과 로딩 속도 개선을 함께 얻을 수 있지만 페이지와 독립된 생명주기 때문에 업데이트 타이밍은 따로 신경 써야 한다.
